# 通用資料（base data）

這裡的每個 `{spaceId}.json` 對應一個內建分區（space-index / space-kwc /
space-beginner / space-goal），存放「官方隨版本更新」的招式與分類。目前全部
是空的，之後要放通用內容時直接編輯對應檔案即可：

```json
{
  "version": 1,
  "categories": [ /* 格式同 db.categories，記得帶上正確的 spaceId */ ],
  "tricks": [ /* 格式同 db.tricks */ ]
}
```

- `version` 是給人看的版本註記（更新內容時順手 +1），程式本身不會用它擋任何
  更新流程 —— 它只是被原封不動存進使用者的雲端差異資料裡，方便日後除錯時
  知道某個帳號的差異是「相對於哪一版通用資料」算出來的。
- 使用者登入後，前端會把 base 資料 + 使用者在 Firestore 裡的「差異」
  （新增／修改／刪除）合併成最終顯示的內容（見 `js/19-auth-sync.js`）。也就是
  說：這裡新增的招式，會自動出現在所有「沒有動過那個項目」的使用者畫面裡；
  使用者若曾修改或刪除某個 base 項目，那筆差異會繼續蓋過 base 的更新內容。
- 自訂分區（使用者自己新增的分區）沒有對應的 base 檔案，一律視為 base 是空的
  （使用者新增的一切都會被記錄成「新增」）。
